# par-mux Design Decisions

One-line summaries of the design decisions that par-mux code comments and docs cite by number (`D3.3`, `T4.C`, …). The full plan, with rationale and alternatives, lives in `par-mux.md` in the `par-agent-os` repository (see [par-mux.md](par-mux.md)). This file keeps the citations resolvable from this repository.

## Decisions

| Id | Decision | Cited in |
|----|----------|----------|
| D1 | `mux` is a cargo feature of this crate, not a separate crate; it is absent from the `default` and `sim` builds. Superseded in part by ARC-007 O2 phase 2: the code now lives in the `par-mux` workspace member, but the root still exposes it only behind its `mux` feature, absent from `default` and `sim` | `crates/par-mux/src/mux/scrape.rs`, `Cargo.toml` (pinned by `tests/mux_feature_isolation.rs`) |
| D2 | The mux runtime types are its own (`MuxSession`, `MuxWindow`, `MuxPane`), separate from the streaming serialization schema (`StreamSessionState` in `src/streaming/session.rs`; the `terminal::multiplexing` schema the original decision named was removed as dead code, persistence having moved to the replay-snapshot types — see D3.1); `src/streaming/mux_factory.rs` cites it for keeping the daemon's pane the only owner of its terminal | `src/streaming/mux_factory.rs` |
| D3 | Parity tier: implement what par-term's tmux client drives, not all of tmux (no copy-mode, buffer stack, or `#{…}` format strings) | `crates/par-mux/src/mux/dispatch/`, `crates/par-mux/src/mux/tree/` |
| D3.1 | Persistence serializes the replay-snapshot types through feature-gated serde derives (`serde` feature), not a DTO layer | `Cargo.toml` |
| D3.2 | The state file is a versioned envelope; an unreadable or unknown-version file is quarantined and the daemon starts fresh | `crates/par-mux/src/mux/persist/{format,restore}.rs`, `crates/par-mux/src/bin/par_mux/daemon.rs` |
| D3.3 | Save after every mutating command and on clean shutdown, atomically (temp file, fsync, rename); losing unsaved content on SIGKILL is accepted. The original synchronous save later moved to an off-lock coalescing worker (ARC-003) | `crates/par-mux/src/mux/dispatch/`, `crates/par-mux/src/mux/command/`, `crates/par-mux/src/mux/persist/save.rs`, `crates/par-mux/src/mux/server/`, `crates/par-mux/src/bin/par_mux/daemon.rs`, [MUX.md](MUX.md#shutdown-semantics) |
| D3.4 | The state file lives in the platform state directory, keyed by socket name, owner-only; the socket itself stays in the runtime/temp directory | `crates/par-mux/src/mux/persist/state_file.rs`, `crates/par-mux/Cargo.toml`, `crates/par-mux/src/bin/par_mux/daemon.rs` |
| D3.5 | Restore rebuilds layout and content with fresh processes: spawn first, then restore the saved screen; id allocation resumes past saved ids | `crates/par-mux/src/mux/persist/restore.rs`, `crates/par-mux/src/mux/server/`, `crates/par-mux/src/mux/ids.rs`, `crates/par-mux/src/mux/pane.rs` |
| D4 | Transport is a cross-platform local socket (Unix socket, Windows named pipe); the WebSocket streaming path is untouched | `crates/par-mux/src/mux/ipc.rs`, `crates/par-mux/Cargo.toml` |
| D5 | The server is a daemon that outlives its clients, and par-term auto-spawns it | `crates/par-mux/Cargo.toml`, `crates/par-mux/src/bin/par_mux/daemon.rs` |
| D5.4 | Reattach resync: the daemon replays a pane's current screen on request (`refresh-client` without `-C`), reusing the terminal's snapshot export | `crates/par-mux/src/mux/dispatch/` |
| D6.2 | An agent's resume invocation is never persisted; it is built at restore time from a table shipped in the binary, with a hook-reported invocation taking precedence | `crates/par-mux/src/mux/agent_resume.rs` |
| D6.3 | Restore respawns agent panes through that invocation and fails safe: when none can be built, the pane spawns its original command | `crates/par-mux/src/mux/agent_resume.rs`, `crates/par-mux/src/mux/persist/restore.rs` |
| D7 | `worktree-create` takes its branch as `-b <branch>`, matching `git worktree add -b`; `-n` keeps one meaning across the command set, the NAME flag of `new-workspace`. Decided 2026-10-19 before the command's first release, when the rename broke nothing. The old `-n` spelling is refused with a pointer to `-b`. Amended 2026-10-20 (Paul): the start point is `--base <base>`, long-only — git's `worktree add -B` means create-or-reset, so keeping a short `-B` would collide with the muscle memory; `-B` is refused with a pointer to `--base`, same as `-n`. Recorded in this repository, not in the `par-agent-os` plan | `crates/par-mux/src/mux/command/worktrees.rs`, `docs/MUX.md` |
| D8 | Snapshot history: every pane-bearing save at least 15 minutes after the newest kept snapshot copies the state file into `snapshots/` beside it (`<stem>-<unix_ms>.state.json`, newest last, capped at 48 — herdr's `session-snapshots/` numbers). The snapshots are persistence's third recovery tier: an unreadable state file restores through `.lastgood`, then the newest snapshot; an empty target state restores through them only when the emptiness was not deliberate (a Reap-origin raced empty), because a deliberate empty save (Command/ShutdownEmpty origin) clears the history tier with `.lastgood` — the fresh-start contract of D3.3 must not be resurrected through a side door. Unlike herdr there is no layout-fingerprint dedupe: par-mux's state embeds live screens, so successive saves are never layout-identical bytes and the interval alone bounds growth | `crates/par-mux/src/mux/persist/save.rs`, [MUX.md](MUX.md#persistence-and-restart) |
| D9 | Linux logind shutdown inhibitor behind the `shutdown-inhibit` feature (off by default): a thread holds a `shutdown` delay lock via login1's `Inhibit` from daemon start, and on `PrepareForShutdown` pushes a Shutdown-origin save to the persist worker, then parks holding the lock — logind caps the delay (`InhibitDelayMaxSec`, default 5 s), so a stuck save costs the window, never the shutdown. Ported from herdr's zbus watcher onto the blocking persist worker. Off by default because zbus is a heavy dependency tree and the Linux CI budget is tight; a build that wants host-shutdown safety enables it explicitly. Absent on non-Linux, without the feature, or when the system bus is unreachable — the daemon serves on without it. | `crates/par-mux/src/mux/shutdown_inhibit.rs`, `crates/par-mux/Cargo.toml`, `crates/par-mux/src/mux/server/mod.rs` |
| D10 | Live handoff (replacing the daemon binary without losing live panes) is designed but deliberately not built: the state file already rebuilds every pane with fresh processes (D3.5), so `par-mux --restart` today is a stop-and-restore handoff that loses only in-flight PTY content since the last save. A true live handoff would: (1) the new binary execs and connects to the running daemon over its control socket with a handoff command, (2) the old daemon passes each pane's PTY master fd across a Unix socket via SCM_RIGHTS (Windows: `DuplicateHandle` into the child, or a ConPTY handle inheritance window) together with the tree capture, (3) the old daemon stops accepting but keeps its event loop until the new daemon acks the full transfer, then exits without a final save (the new daemon owns the state now). The design is recorded here for whenever pane-survival across an update becomes a requirement; until then the stop-and-restore path is the contract | `crates/par-mux/src/mux/update.rs`, `docs/MUX.md` (Persistence and Restart) |
| T4.B | `send-keys` contract: key names, `-l` literal, `-H` hex, and no implicit trailing newline | `crates/par-mux/src/mux/command/` |
| T4.C | Sizing: pane terminals re-fit to layout geometry after every change; `resize-pane -x/-y`; `refresh-client -C` sizes the window to the componentwise minimum over the render clients displaying it (tmux `window-size smallest`), and a larger client pads the space past the window with `.` cells. A report that does not move the window answers the issuer alone, so two differently-sized clients cannot re-report each other into a re-seed flip-flop. (A latest-attached-client rule briefly replaced the minimum on 2026-10-13; it clipped the shorter of two terminals and was reverted.) | `crates/par-mux/src/mux/command/`, `crates/par-mux/src/mux/tree/`, `crates/par-mux/src/mux/attach/` |
| T4.E | Queries have fixed reply shapes and no `-F` format strings; push notifications cover what `-F` polling was for | `crates/par-mux/src/mux/dispatch/` |
| R7 | par-mux owns agent state for the panes in its sessions and never reconciles another tool's roster; par-term consumes that state rather than becoming a second owner. Recorded in `REPORT.md` in the same repository; `src/streaming/mux_factory.rs` applies the same no-second-owner rule to pane terminals | `src/streaming/mux_factory.rs` |

Test files under `crates/par-mux/tests/mux_*.rs` also cite D3.3 and D3.5 for the behavior they pin.
