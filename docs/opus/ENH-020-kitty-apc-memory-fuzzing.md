# ENH-020: Memory-bounded fuzzing for the Kitty/APC path (`-rss_limit_mb`) plus an `apc_filter` target

> Filed from the 2026-09-26 run-2 /opus-audit enhancement pass (cycle `audit-2026-09-26-r2`). Board card: `[ENH-020]` (priority medium, estimate S).
> Complements AUDIT SEC-109 (the fix). This card makes the fuzzer able to *find* that class of bug.

## Goal

SEC-109 (a zlib decompression bomb, 581 MB peak RSS from a 700 KB APC) went unnoticed even though `fuzz/fuzz_targets/kitty.rs` exists. The target never exercises `o=z`, and it runs under libFuzzer's default RSS limit (2048 MB), so a bomb that stays below 2 GiB is not flagged. This enhancement:
- makes memory blowups count as fuzz failures,
- seeds the compressed path, and
- covers `apc_filter` (the byte-level APC accumulator), which currently has no fuzz target.

## Current state

- `fuzz/fuzz_targets/{terminal_process,sixel,kitty,tmux_control,mux_parse_command,mux_hook_report}.rs`.
- `kitty.rs` decodes input lossily, splits on ST, and calls `KittyParser::parse_chunk` and `build_graphic` (see the file header).
- `fuzz.yml` runs 4 targets nightly with `-max_total_time=600` and no `-rss_limit_mb` (see AUDIT ARC-057 for the missing mux targets).
- `fuzz/corpus/kitty/` exists. Check its contents for `o=z` seeds.
- `src/terminal/apc_filter.rs` holds the APC state machine (`ApcFilterState`, `apc_buffer`) that feeds `on_kitty`.

## Implementation

1. **Seeds**: add 3 to 5 corpus files under `fuzz/corpus/kitty/`, generated by a small script `fuzz/seeds/gen_kitty_zlib.py` (stdlib `zlib` + `base64`):
   - `a=T,f=32,s=2,v=2,o=z;<b64(zlib(16 bytes))>`
   - an `m=1` chunked version of the same payload
   - a 4 KiB zlib payload that expands to 1 MiB of zeros

   Commit the script and its outputs.
2. **New target** `fuzz/fuzz_targets/apc_filter.rs`: feed raw bytes through the public entry point that drives `apc_filter` into the terminal. The simplest option is `Terminal::new(80,24).process(data)`, but that duplicates `terminal_process`. The better option is to call the filter function directly. If it is `pub(crate)`, add a `#[doc(hidden)] pub fn fuzz_apc_filter(data: &[u8])` behind `#[cfg(fuzzing)]`, the standard cargo-fuzz cfg.
   - Invariant: no panic, and no single allocation above a cap. The rss limit enforces the cap.
3. **RSS limit everywhere**: in `fuzz.yml` and the Makefile `fuzz-*` targets, append `-rss_limit_mb=512` to every run. That value is well above normal parser needs (check with `make fuzz-terminal_process FUZZ_SECONDS=30` that no target legitimately exceeds it; raise it to 768 if needed and note why).
4. Add `apc_filter` to `fuzz/Cargo.toml` `[[bin]]`, the `fuzz.yml` matrix and `fuzz-all`.
5. **Expected result before SEC-109 lands**: the kitty target with the new seeds and `-rss_limit_mb=512` should crash quickly with an out-of-memory report. Record the reproducer path in the card notes as the proof that the gate works. If SEC-109 has already landed, the run must stay clean.
