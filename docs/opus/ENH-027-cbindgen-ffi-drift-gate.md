# ENH-027: Generate `terminal_core.h` with cbindgen and gate FFI surface drift in `checkall`

> Filed from the 2026-09-28 /opus-audit enhancement pass (cycle `audit-2026-09-28`). Board card: `[ENH-027]`.
> Sequencing: land after AUDIT ARC-063 (ABI version constant) and QA-151 (`key: u16`), so the generated header reflects the fixed layout. This enhancement is the tooling. ARC-063 is the defect fix, and the two are separate cards on purpose.

## Goal

Make `include/terminal_core.h` impossible to drift from `src/ffi.rs`/`src/keyboard.rs`, and make undocumented FFI functions impossible. Three guards:

1. The header is generated by `cbindgen` from the Rust `#[repr(C)]` types and `extern "C"` functions. A `make ffi-header-check` target regenerates it to a temp file and diffs it against the committed header.
2. `scripts/check_ffi_surface.py` verifies that every `#[no_mangle] extern "C" fn` in `src/ffi.rs` appears in `docs/FFI_GUIDE.md`. This is the doc-side gate for DOC-065/070-style drift.
3. Both run in `checkall`. Neither needs Xcode.

## Current state

- `include/terminal_core.h` is hand-written: structs, `TERM_*` macros, prototypes, and `_Static_assert` layout checks. The Rust side pins layout with `offset_of!` tests in `src/ffi.rs`.
- `scripts/build-xcframework.sh` smoke-compiles the header and runs link and Swift probes, but only on macOS with Xcode, outside `checkall`.
- DOC-065/070 found the FFI guide missing all 12 embedding functions. Nothing checks it.
- `cbindgen` is installed locally (`~/.cargo/bin/cbindgen`). It is not a project dependency.

## Implementation

1. Add `cbindgen.toml` at the repo root:
   - `language = "C"`, `include_guard = "TERMINAL_CORE_H"`, `sys_includes = ["stdint.h","stdbool.h","stddef.h"]`, `no_includes = true`.
   - `[export] include = ["SharedCell","SharedState","TermRowRange","TermCursorState","TermModeState","TermKeyEvent", …]`, `prefix = ""`.
   - `[parse] parse_deps = false`, and `[defines]` for `feature = ffi` (if ARC-077 gated it).
   - A `header` field carrying the current hand-written preamble comment (ownership contract, threading, panic, ABI version notes). Move that prose there verbatim.
2. Convert the `TERM_*` `#define`s. Constants that live in Rust (`modifiers::*`, cell flag bits, mouse modes, `TERM_CORE_ABI_VERSION`) should be `pub const` items cbindgen emits. `TermKey` values become `pub const TERM_KEY_*: u16` in `keyboard.rs`, since the FFI field is `u16` after QA-151. Keep the enum Rust-side and add a test asserting each const equals `TermKey::X as u16`.
3. `_Static_assert`s: cbindgen does not emit them. Keep them in a small hand-written `include/terminal_core_layout.h` that the generated header includes via `trailer = "#include \"terminal_core_layout.h\""`. Alternatively, rely on the Rust `offset_of!` tests plus a C test compile. Pick the trailer approach so C consumers still get compile-time checks.
4. Makefile targets:
   - `ffi-header`: `cbindgen --config cbindgen.toml --crate par-term-emu-core-rust --output include/terminal_core.h`
   - `ffi-header-check`: `cbindgen … --output $(TMP)/h && diff -u include/terminal_core.h $(TMP)/h`
   - `ffi-surface-check`: `uv run python scripts/check_ffi_surface.py`
   - Add both checks to `checkall`. If `cbindgen` is missing, `ffi-header-check` prints an install hint and fails. Add `cargo install cbindgen --locked` to `make setup-venv` or document it in BUILDING.md.
5. `scripts/check_ffi_surface.py`:
   - Parse `src/ffi.rs` for `#[no_mangle]` followed by `pub (unsafe )?extern "C" fn (\w+)`.
   - Parse `include/terminal_core.h` for prototypes.
   - Parse `docs/FFI_GUIDE.md` for backticked function names.
   - Exit 1 listing any function missing from the header or the guide.
   - Tolerate an allowlist in the script for deliberately undocumented internals (should be empty).
6. First run: generate, then diff against the hand-written header. Differences must be formatting only. Any semantic difference (a type width, a missing field) is a real bug. Fix the Rust side and record it in the PR.

## Files to touch

- `src/ffi.rs`, `src/keyboard.rs` (consts that cbindgen exports)
- `scripts/check_ffi_surface.py` (new), `Makefile`

## Verify

- `make ffi-header-check` exits 0 on a clean tree, and exits 1 after adding a dummy field to `TermCursorState` without regenerating (revert after).
- `make ffi-surface-check` exits 0, and exits 1 after temporarily removing one function name from FFI_GUIDE.md.
- `make xcframework` still passes the header smoke-compile, link and Swift-import probes (macOS).
- `cargo test --lib --no-default-features --features pyo3/auto-initialize ffi` passes (layout tests plus the TERM_KEY const test).
- `make checkall` is green.

## Rollback

Revert to the committed hand-written header (it is in git history), and remove the two check targets from `checkall`. No runtime behavior changes.
