# FFI Guide

How to embed the terminal emulator from C, C++, Swift, or any language with a C FFI. The surface lives in [`include/terminal_core.h`](../include/terminal_core.h), generated by cbindgen from `src/ffi.rs` (ENH-027): the Rust types are `#[repr(C)]`, and the `TERM_*` constants plus `_Static_assert` layout pins live in the hand-written companion `terminal_core_layout.h` that the generated header includes — so header and library cannot drift apart silently (`make ffi-header-check` and `make ffi-surface-check` gate it in `checkall`).

- **Embedding functions** — `ptec_terminal_abi_version`, `ptec_terminal_create`/`ptec_terminal_free`, `ptec_terminal_feed`, `ptec_terminal_resize`, `ptec_terminal_dirty_ranges`/`ptec_terminal_mark_clean`, `ptec_terminal_damage_generation`/`ptec_terminal_dirty_ranges_since`, `ptec_terminal_scroll_delta_since`/`ptec_terminal_content_dirty_ranges_since`, `ptec_terminal_read_row`/`ptec_terminal_read_scrollback_row`/`ptec_terminal_read_cell_grapheme`/`ptec_terminal_scrollback_count`/`ptec_terminal_scrollback_total_scrolled`, `ptec_terminal_get_cursor`/`ptec_terminal_get_modes`, `ptec_terminal_encode_key`/`ptec_terminal_encode_key_ex`
- **Snapshot functions** — `ptec_terminal_get_state`/`ptec_terminal_free_state`
- **Observer functions** — `ptec_terminal_add_observer`/`ptec_terminal_remove_observer`
- **Types** — `Terminal` (opaque), `SharedCell`, `SharedState`, `TermRowRange`, `TermCursorState`, `TermModeState`, `TermKeyEvent`, `TermKeyOptions`, `TerminalObserverVtable`, `TermEvent`

The intended embedding shape is a **damage-driven render loop** (below): the host feeds PTY bytes in, asks which rows changed, reads only those rows into its own buffers, and encodes keyboard input back out. The `SharedState` snapshot and the observer vtable cover the cases a renderer does not handle per-frame (full-state queries, shell-integration events).

**Cross-cutting contracts** (from the header):

- **Single-threaded handles.** No concurrent calls on one `Terminal`; synchronize externally if you share it.
- **No panic catching.** No entry point catches a Rust panic — a panic inside any call aborts the host process (Rust 1.81+ abort-on-FFI-unwind semantics). Allocation failure is likewise fatal: this surface has no error channel, so out-of-memory aborts by design.
- **Reads target the active grid.** While the alternate screen is active, `ptec_terminal_scrollback_count` returns 0 — the alternate screen has no scrollback.

## Building

The crate's everyday `crate-type` is `cdylib, rlib` (Python extension + Rust library), so a plain `cargo build` produces **no** static library. To get a C-linkable `.a`, override the crate type for one invocation:

```bash
# Static library (.a) for the host target — what a C/C++ app links against
cargo rustc --lib --crate-type staticlib --release \
    --no-default-features --features rust-only,ffi

# Output: target/release/libpar_term_emu_core_rust.a
```

- The `ffi` feature compiles the C surface (`src/ffi.rs`). It is off by default, so Python wheels and Rust embedders export no `ptec_terminal_*` symbols; a build without it links but has none of the functions below.
- The `rust-only` feature drops the Python bindings (the default `python` feature links the host's libpython, which cannot link into a binary that embeds no interpreter).
- A dynamic library is available through the `cdylib` crate type (`cargo build --release --no-default-features --features rust-only,ffi`), but embedding is normally done against the static library so the linker can drop unused code. The Python extension from `make dev` does not carry the C surface.

### iOS / Apple platforms

make xcframework

`scripts/build-xcframework.sh` builds staticlibs for `aarch64-apple-ios` and `aarch64-apple-ios-sim`, smoke-compiles the header for both targets (running its `_Static_assert`s), packages `TerminalCore.xcframework` with `include/` as the headers, and writes a `Modules/module.modulemap` into every slice so Swift consumers can `import TerminalCore` (see [Swift](#swift-import-terminalcore)). ## Lifecycle

```c
#include "terminal_core.h"

Terminal *make_terminal(void) {
    return ptec_terminal_create(80, 24, 10000); /* cols, rows, scrollback */
}
```

- `ptec_terminal_create(cols, rows, scrollback)` returns `NULL` when `cols` or `rows` is 0.
- `ptec_terminal_free(term)` releases the handle; `NULL` is a no-op.
- `ptec_terminal_resize(term, cols, rows)` reflows the grid; a zero dimension is a no-op.

On first use, compare `ptec_terminal_abi_version()` against `TERM_CORE_ABI_VERSION` (see [ABI Version](#abi-version)).

## Render Loop

The per-frame cycle is `ptec_terminal_feed` → `ptec_terminal_dirty_ranges` → `ptec_terminal_read_row` (per dirty range) → `ptec_terminal_mark_clean`:

1. **Feed** raw application/PTY output bytes (`ptec_terminal_feed`). VT parsing happens inline.
2. **Size the damage** — `ptec_terminal_dirty_ranges(term, NULL, 0)` returns the total number of coalesced dirty-row ranges without writing anything.
3. **Fetch the ranges** into a buffer of that size. Every call returns the *total* range count; if the terminal dirtied more rows between the two calls, the return exceeds your capacity and you retry larger.
4. **Read only the dirty rows** with `ptec_terminal_read_row` into a caller-owned buffer — no allocation, no full-grid copy.
5. **`ptec_terminal_mark_clean`** clears the damage set once the frame is drawn.

```c
#include "terminal_core.h"
#include <stdio.h>
#include <stdlib.h>

/* One frame: feed bytes, then print the rows that changed. Returns 0 on
 * success, -1 on allocation failure. */
int render_frame(Terminal *term, const uint8_t *bytes, uint32_t len) {
    ptec_terminal_feed(term, bytes, len);

    /* Size the damage: NULL out + cap 0 returns the total range count. */
    uint32_t total = ptec_terminal_dirty_ranges(term, NULL, 0);
    if (total == 0) {
        return 0; /* nothing changed */
    }

    TermRowRange *ranges = malloc(sizeof(TermRowRange) * total);
    if (!ranges) {
        return -1;
    }
    uint32_t written = ptec_terminal_dirty_ranges(term, ranges, total);
    while (written > total) { /* damage grew between the two calls */
        total = written;
        TermRowRange *grown = realloc(ranges, sizeof(TermRowRange) * total);
        if (!grown) {
            free(ranges);
            return -1;
        }
        ranges = grown;
        written = ptec_terminal_dirty_ranges(term, ranges, total);
    }

    for (uint32_t i = 0; i < written; i++) {
        uint32_t row = ranges[i].start;
        while (row <= ranges[i].end) {
            /* Size the row: NULL out + cap 0 returns the cells available
             * from col_start. Reading a full row: col_start = 0. */
            uint32_t cells = ptec_terminal_read_row(term, row, 0, NULL, 0);
            SharedCell *buf = malloc(sizeof(SharedCell) * (cells ? cells : 1));
            if (!buf) {
                free(ranges);
                return -1;
            }
            uint32_t n = ptec_terminal_read_row(term, row, 0, buf, cells);
            for (uint32_t c = 0; c < n; c++) {
                printf("%.*s", (int)buf[c].text_len, (const char *)buf[c].text);
            }
            printf("\n");
            free(buf);
            row++;
        }
    }

    free(ranges);
    ptec_terminal_mark_clean(term);
    return 0;
}
```

### Per-Consumer Damage

`ptec_terminal_dirty_ranges`/`ptec_terminal_mark_clean` serve one built-in default consumer: `mark_clean` advances that consumer and the next `dirty_ranges` call reports only newer edits. When more than one renderer watches the same `Terminal` (an FFI renderer plus the Python `get_dirty_rows` default consumer, say), one consumer repainting must not hide damage from the other.

For that, use the generation pair: remember `ptec_terminal_damage_generation(term)` instead of calling `mark_clean`, and query `ptec_terminal_dirty_ranges_since(term, gen, out, cap)` with the remembered value. Same buffer contract as `ptec_terminal_dirty_ranges` (NULL/0 sizing call, total-count return). Consumers that hold their own generations never interact — each sees every edit after the generation it captured. A screen switch dirties every row of the newly visible grid for any older generation.

`ptec_terminal_read_row(term, row, col_start, out, cap)` writes up to `cap` cells starting at `col_start` and returns the number written; with `out == NULL` and `cap == 0` it returns the number of cells available from `col_start` (the sizing answer). Rows are 0-indexed.

### Scroll-Aware Damage

One line of output dirties every row positionally, but all but one row only *moved*. ABI v5 adds the additive pair `ptec_terminal_scroll_delta_since` / `ptec_terminal_content_dirty_ranges_since` (ENH-038) so a renderer can blit the rows that survived a scroll and redraw only the rows whose content actually changed:

```c
uint64_t gen = ptec_terminal_damage_generation(term);

/* each frame: */
TermScrollDelta scroll;
if (ptec_terminal_scroll_delta_since(term, gen, &scroll)
    && !(scroll.flags & TERM_SCROLL_FULL_REDRAW)) {
    /* Blit the previous frame's rows [scroll.top, scroll.bottom] shifted by
     * scroll.delta rows (positive = content moved up); rows the blit vacates
     * are cleared and always appear in the content-dirty set. */
    TermRowRange ranges[16];
    uint32_t total = ptec_terminal_content_dirty_ranges_since(term, gen, ranges, 16);
    for (uint32_t i = 0; i < total && i < 16; i++)
        for (uint32_t r = ranges[i].start; r <= ranges[i].end; r++)
            ptec_terminal_read_row(term, r, 0, frame + r * cols, cols);
} else {
    /* Sentinel: blitting cannot express the change (screen switch, resize or
     * reflow, RIS, snapshot restore, scrollback clear, scroll-log overflow,
     * mixed scroll regions) — fall back to a full redraw. */
}
gen = ptec_terminal_damage_generation(term);
```

`TERM_SCROLL_FULL_REDRAW` (bit 0 of `TermScrollDelta.flags`) is the fallback contract; a renderer that ignores the scroll pair entirely and uses only `ptec_terminal_dirty_ranges_since` sees identical results to ABI v4. The report is per active grid: `ptec_terminal_scrollback_total_scrolled` is deliberately *not* a scroll-damage source (it only moves when rows enter scrollback, stays 0 on the alt screen and in DECSTBM sub-regions, and resets on `3J`) — it exists solely to sync a mirrored scrollback window.

Each `SharedCell` carries up to 4 UTF-8 bytes of the base character (`text`/`text_len`), RGB foreground and background, an `attrs` bitfield, and the display `width` (1 or 2 — a wide CJK/emoji cell is followed by a `TERM_CELL_WIDE_CHAR_SPACER` cell).

**Colors are display colors** (ABI v4, ARC-101), resolved the way the Python snapshot resolves them:

- The 16 base colors (SGR 30–37/40–47/90–97/100–107, and `38;5;0`–`15`) follow the live ANSI palette, so `OSC 4` recolors them. The 256-color cube, the grayscale ramp and 24-bit RGB are fixed.
- A **default** color resolves through the terminal's default foreground/background (`OSC 10`/`OSC 11`) and sets `TERM_ATTR_DEFAULT_FG` / `TERM_ATTR_DEFAULT_BG` in `attrs`, so a renderer with its own theme can substitute it. Default is recognized by value: a color equal to the unstyled color or to the *current* OSC 10/11 value. An explicit SGR 37/40 is indistinguishable from the default and is flagged the same way. A cell written after SGR 0/39/49 stores the default of that moment, so if OSC 10/11 later changes again it keeps its old color and is no longer flagged.
- Bold brightening (on by default) maps a bold ANSI 0–7 foreground to its bright 8–15 slot.
- Reverse video, dim and hidden are **not** applied — they stay `TERM_CELL_*` bits for the renderer.

`attrs` bits 0–11 are the `TERM_CELL_*` attributes; bits 12–14 are the readback bits `TERM_ATTR_DEFAULT_FG`, `TERM_ATTR_DEFAULT_BG` and `TERM_ATTR_HAS_COMBINING`.

### Combining marks: `ptec_terminal_read_cell_grapheme`

`text` holds only the base character. A cell whose `attrs` has `TERM_ATTR_HAS_COMBINING` also carries combining marks (accents, variation selectors, ZWJ sequences); fetch the whole cluster with `ptec_terminal_read_cell_grapheme(term, row, col, out, cap)`:

```c
if (cell.attrs & TERM_ATTR_HAS_COMBINING) {
    uint8_t cluster[64];
    uint32_t total = ptec_terminal_read_cell_grapheme(term, row, col, cluster, sizeof(cluster));
    /* total <= sizeof(cluster): cluster[0..total] is the UTF-8 grapheme.
     * total > sizeof(cluster): retry with a buffer of `total` bytes. */
}
```

It uses the same cap/return-total protocol as the other buffer reads (`out` NULL with `cap` 0 sizes it), writes no NUL terminator, addresses the active grid like `ptec_terminal_read_row`, and returns 0 for a position outside the grid.

## Scrollback

```c
#include "terminal_core.h"
#include <stdio.h>

/* Print the oldest scrollback line. Lines run from oldest (0) to newest
 * (count - 1); the visible grid is NOT part of this numbering. */
void print_first_scrollback_line(Terminal *term) {
    uint32_t count = ptec_terminal_scrollback_count(term);
    if (count == 0) {
        return; /* empty, or the alternate screen is active */
    }
    uint32_t cells = ptec_terminal_read_scrollback_row(term, 0, 0, NULL, 0);
    SharedCell buf[512];
    uint32_t n = ptec_terminal_read_scrollback_row(
        term, 0, 0, buf,
        cells < 512 ? cells : 512);
    for (uint32_t c = 0; c < n; c++) {
        printf("%.*s", (int)buf[c].text_len, (const char *)buf[c].text);
    }
    printf("\n");
}
```

`ptec_terminal_read_scrollback_row` has the same cap/return protocol as `ptec_terminal_read_row`. While the alternate screen is active, `ptec_terminal_scrollback_count` returns 0.

### Window sync (eviction without a full re-read)

`ptec_terminal_scrollback_total_scrolled` is the total of lines ever pushed into scrollback. Paired with the count it defines the window an embedder mirrors: the buffer holds lines `[total - count, total)`. A frame's head evictions and tail appends both follow from the two counters' deltas, including when the ring is full and the count alone has frozen at the cap — the case a count-delta mirror cannot see. The invariant `count == min(total, cap)` holds on every pure window slide; a violation (screen switch, reflow) is the consumer's signal to re-read the whole window instead of sliding. The total resets to 0 together with the count on `clear_scrollback` (ED 3J). It counts buffer entries only — alt-screen and in-region scrolls that never reach scrollback do not move it, so it is a window cursor, not a scroll-damage source.

## Cursor and Modes

Per-frame renderer state, written into caller-owned structs (no allocation):

```c
#include "terminal_core.h"

void print_frame_state(Terminal *term) {
    TermCursorState cursor; /* .col, .row (0-indexed), .visible, .style */
    ptec_terminal_get_cursor(term, &cursor);

    TermModeState modes; /* alt_screen, bracketed_paste, application_cursor,
                            origin_mode, insert_mode, auto_wrap, mouse_mode,
                            kitty_flags, cols, rows */
    ptec_terminal_get_modes(term, &modes);
}
```

`cursor.style`: 0 blinking block, 1 steady block, 2 blinking underline, 3 steady underline, 4 blinking bar, 5 steady bar. `modes.mouse_mode` uses the `TERM_MOUSE_MODE_*` constants; `modes.kitty_flags` are the kitty keyboard progressive-enhancement flags the application negotiated (relevant to [key encoding](#key-encoding)).

## Key Encoding

`ptec_terminal_encode_key(term, &ev, out, cap)` encodes a key event against the terminal's **negotiated input state** (application cursor keys, kitty keyboard flags) — the exact bytes a frontend writes to the PTY. It uses the same cap/return-total protocol as the buffer reads: it writes up to `cap` bytes and returns the *total* encoded length; if the return exceeds `cap`, retry with a larger buffer. A return of 0 means the event encodes to nothing.

```c
#include "terminal_core.h"

/* Send "Ctrl+Left arrow" to the application, honoring whatever key
 * protocol it negotiated. Returns bytes written, or the needed size. */
uint32_t send_ctrl_left(Terminal *term) {
    TermKeyEvent ev = {
        .key = TERM_KEY_LEFT,
        .modifiers = TERM_MOD_CTRL,
        .codepoint = 0, /* only meaningful for TERM_KEY_CHAR */
    };
    uint8_t buf[32];
    uint32_t total = ptec_terminal_encode_key(term, &ev, buf, sizeof(buf));
    /* total <= sizeof(buf): write buf[0..total] to the PTY.
     * total > sizeof(buf): retry with a buffer of `total` bytes. */
    return total;
}
```

- `TermKeyEvent.key` is a `TERM_KEY_*` constant. Functional-key values **are** the kitty protocol functional codes (e.g. `TERM_KEY_LEFT` is 57428) — do not renumber or remap them.
- For `TERM_KEY_CHAR`, set `codepoint` to the Unicode scalar: the typed form for plain text, the base form for Ctrl/Alt combinations.
- Any `uint16_t` key value is accepted; values that are not a `TERM_KEY_*` constant encode to zero bytes.
- `modifiers` is a bitfield of `TERM_MOD_SHIFT`, `TERM_MOD_ALT`, `TERM_MOD_CTRL`, `TERM_MOD_SUPER`, `TERM_MOD_HYPER`, `TERM_MOD_META` (kitty protocol order), plus the side-info bit `TERM_MOD_ALT_RIGHT`.
- The encoder covers the terminal's negotiated **modifyOtherKeys** mode (`CSI > 4 ; Pv m`): with mode 1 or 2 active, text keys with Ctrl or Alt held encode as `CSI 27 ; mods ; codepoint ~`.

### Option-key modes: `ptec_terminal_encode_key_ex`

`ptec_terminal_encode_key` uses the default macOS Option-key handling (ESC prefix — the classic xterm Alt). `ptec_terminal_encode_key_ex(term, &ev, &opts, out, cap)` takes an explicit `TermKeyOptions` for per-side Option-key modes; `opts` may be NULL for those same defaults, and a zeroed struct means `TERM_OPTION_MODE_NORMAL` on both sides.

```c
/* Right Option = Meta (8th bit), left Option = Esc prefix. */
TermKeyOptions opts = {
    .left_option = TERM_OPTION_MODE_ESC,
    .right_option = TERM_OPTION_MODE_META,
};
TermKeyEvent ev = {
    .key = TERM_KEY_CHAR,
    .modifiers = TERM_MOD_ALT | TERM_MOD_ALT_RIGHT, /* right Option key */
    .codepoint = 'a', /* base form when Alt drives the encoding */
};
uint8_t buf[32];
uint32_t total = ptec_terminal_encode_key_ex(term, &ev, &opts, buf, sizeof(buf));
/* buf[0] == 0xE1 — 'a' with the 8th bit set. */
```

- Modes: `TERM_OPTION_MODE_NORMAL` (pass the OS-composed character through — send the composed glyph in `codepoint`), `TERM_OPTION_MODE_META` (8th bit on ASCII base characters, ESC prefix otherwise), `TERM_OPTION_MODE_ESC` (ESC-prefix the base character).
- `TERM_MOD_ALT_RIGHT` selects `right_option`; without it (or when both Alt keys are down) `left_option` applies. It is side info only — no xterm/kitty parameter field counts it.
- Option modes apply to the legacy encoding only. Under the kitty keyboard protocol the application decodes Alt itself, and under modifyOtherKeys the 27-form outranks the option modes.

## Snapshot: SharedState

For a full-state query (saving state, drawing a complete frame, debugging), `ptec_terminal_get_state` returns a heap-allocated `SharedState` owned by the caller:

```c
#include "terminal_core.h"
#include <stdio.h>

void print_terminal_state(const Terminal *term) {
    SharedState *state = ptec_terminal_get_state(term);
    if (!state) {
        fprintf(stderr, "ptec_terminal_get_state failed\n");
        return;
    }

    printf("Terminal: %u cols x %u rows\n", state->cols, state->rows);
    printf("Cursor: (%u, %u) visible=%d\n",
           state->cursor_col, state->cursor_row, state->cursor_visible);
    printf("Title: %s\n", state->title);
    printf("CWD: %s\n", state->cwd ? state->cwd : "(none)");
    printf("Alt screen: %d\n", state->alt_screen_active);
    printf("Scrollback: %u lines\n", state->scrollback_lines);
    printf("Total lines: %u\n", state->total_lines);

    if (state->cell_count > 0) {
        SharedCell *cell = &state->cells[0];
        printf("First cell: '%.*s' attrs=0x%04x width=%u\n",
               (int)cell->text_len, (const char *)cell->text,
               cell->attrs, cell->width);
        if (cell->attrs & TERM_CELL_BOLD) printf("  - Bold\n");
        if (cell->attrs & TERM_CELL_ITALIC) printf("  - Italic\n");
    }

    ptec_terminal_free_state(state); /* also invalidates title, cwd, cells */
}
```

### Ownership rules

```mermaid
graph TD
    A[ptec_terminal_get_state] -->|returns owned| B[SharedState]
    B -->|owns| C[title string]
    B -->|owns| D[cwd string or NULL]
    B -->|owns| E[cells array]
    F[ptec_terminal_free_state] -->|frees| B

    classDef api fill:#0d47a1,stroke:#2196f3,stroke-width:2px,color:#ffffff
    classDef owned fill:#1b5e20,stroke:#4caf50,stroke-width:2px,color:#ffffff
    classDef free fill:#FFC107,stroke:#FFC107,stroke-width:2px,color:#1E1E1E
    class A api
    class B,C,D,E owned
    class F free
```

1. You own the `SharedState*` from `ptec_terminal_get_state()`; release it with `ptec_terminal_free_state()` (NULL is a no-op).
2. The `title`, `cwd`, and `cells` pointers are valid **only** until that call — they are freed with the struct; never free them directly.
3. Strings are NUL-terminated UTF-8 with `*_len == strlen(...)`. Interior NULs in the source title are replaced with U+FFFD, never truncated.
4. `cells` holds `cell_count` (= `cols * rows`) entries in row-major order.

You may hold any number of snapshots; they are independent copies, not live views. For per-frame rendering prefer the [render loop](#render-loop) — a snapshot copies the whole grid every call.

## Observers

Register a vtable to receive terminal events inline as `ptec_terminal_feed` parses (and during `ptec_terminal_resize`, which can scroll zones out):

```c
#include "terminal_core.h"
#include <stdio.h>

static void on_screen_event(void *user_data, const char *event_text) {
    printf("[%s] %s\n", (const char *)user_data, event_text);
}

void observer_example(void) {
    Terminal *term = ptec_terminal_create(80, 24, 1000);
    if (!term) return;

    TerminalObserverVtable vtable = {
        .on_screen_event = on_screen_event,
        .user_data = (void *)"screen",
    };
    uint64_t id = ptec_terminal_add_observer(term, vtable);

    static const uint8_t clear[] = "\033[2J";
    ptec_terminal_feed(term, clear, sizeof(clear) - 1); /* fires ScreenCleared */

    ptec_terminal_remove_observer(term, id);
    ptec_terminal_free(term);
}
```

### Event routing

| Callback | Fires for |
|----------|-----------|
| `on_zone_event` | OSC 133 / FinalTerm shell-integration **zones**: `ZoneOpened`, `ZoneClosed`, `ZoneScrolledOut` (prompt/command/output blocks) |
| `on_command_event` | `ShellIntegrationEvent` (OSC 133 `prompt_start`, `command_start`, `command_executed`, `command_finished`) |
| `on_environment_event` | `CwdChanged`, `EnvironmentChanged`, `RemoteHostTransition`, `SubShellDetected` |
| `on_screen_event` | everything else — `TitleChanged`, `BellRang`, `SizeChanged`, `ModeChanged`, `ScreenCleared`, `DirtyRegion`, graphics/hyperlink/transfer events, … |
| `on_event` | catch-all: every event, in addition to its category callback |

| `on_event_v2` | every event, as a structured `TermEvent` (see [Structured events](#structured-events-on_event_v2)) |

All callbacks are optional (NULL slots are skipped, and a NULL slot's text or JSON is never built).

### Structured events: `on_event_v2`

`on_event_v2(user_data, const TermEvent *ev)` is the event channel to build behavior on (ABI v4, ARC-114):

- `ev->kind` is a `TERM_EVENT_*` constant (`TERM_EVENT_TITLE_CHANGED`, `TERM_EVENT_SHELL_INTEGRATION`, `TERM_EVENT_CWD_CHANGED`, …) — one per event kind, stable, never renumbered.
- `ev->payload` / `ev->payload_len` is a UTF-8 **JSON object**, length-delimited and **not NUL-terminated**. Its keys are the event's named fields — the same keys as the Python event dicts (`"type"`, `"title"`, `"exit_code"`, …); an unset optional field is present as `null`. Text travels as JSON strings, so a NUL inside a title or command arrives escaped (`\u0000`) instead of cutting the event short.
- It fires once per event (not once per category).

```c
static void on_event_v2(void *user_data, const TermEvent *ev) {
    if (ev->kind == TERM_EVENT_TITLE_CHANGED) {
        /* e.g. {"type":"title_changed","title":"vim"} */
        printf("title event: %.*s\n", (int)ev->payload_len, (const char *)ev->payload);
    }
}
```

### Payload and re-entry contracts

- The text slots' `event_text` parameter is the Rust `Debug` formatting of the event (`format!("{:?}", event)`), **not JSON**. It is diagnostic text with **no stable format** — it changes whenever the Rust event enum changes. Parse it only for logging; gate no behavior on its shape (use `on_event_v2` for that). An interior NUL in the text is replaced with U+FFFD; the event is never dropped.
- Every pointer (`event_text`, the `TermEvent` and its `payload`) is valid only for the duration of the callback; do not free it, do not store it.
- **No re-entry.** Callbacks fire inline while the terminal is mutably borrowed for the dispatch — a callback must not call any `ptec_terminal_*` function on the same handle; re-entry is undefined behavior. Copy what you need out and act after `ptec_terminal_feed` / `ptec_terminal_resize` returns.
- The vtable (including its `user_data`) must stay valid for the lifetime of the registration; the library never takes ownership of it. `ptec_terminal_add_observer` returns an id for `ptec_terminal_remove_observer` (returns `true` if the observer was found).

## Swift: `import TerminalCore`

`make xcframework` writes a `module.modulemap` into every slice of `TerminalCore.xcframework`, so after dragging the xcframework into an Xcode project:

```swift
import TerminalCore

let term = ptec_terminal_create(80, 24, 10_000)
defer { ptec_terminal_free(term) }

ptec_terminal_feed(term, bytes, UInt32(bytes.count))
var cursor = TermCursorState(col: 0, row: 0, visible: false, style: 0)
ptec_terminal_get_cursor(term, &cursor)
```

The Swift names are the C names unchanged; struct initializers are memberwise. Without the module map (e.g. consuming just the `.a` + header), a bridging header with `#include "terminal_core.h"` works too.

## ABI Version

`TERM_CORE_ABI_VERSION` (in the header) and `ptec_terminal_abi_version()` (in the library) are the contract version of this surface — struct layouts, function signatures, and the behavioral contracts above. They are bumped together on any layout or contract change to the C surface. v1–v3 were additive, each keeping the previous surface; **v4 is a breaking revision** (audit decision D4); v5 is additive again. Versions before v4 used the unprefixed `terminal_*` names:

| Version | First release | Changes |
|---------|---------------|---------|
| v1 | none (development builds only; 0.56.0 shipped v2) | The initial embedding surface: `terminal_abi_version`, lifecycle, `terminal_feed`, `terminal_dirty_ranges`/`terminal_mark_clean`, row and scrollback readback, cursor and mode state, `terminal_encode_key`, snapshots, and observers |
| v2 | 0.56.0 | Adds per-consumer damage: `terminal_damage_generation`, `terminal_dirty_ranges_since` |
| v3 | 0.57.0 | Adds per-side Option-key modes: `TermKeyOptions`, `terminal_encode_key_ex`, `TERM_MOD_ALT_RIGHT`, `TERM_OPTION_MODE_*` |
| v4 | 0.58.0 | **Breaking.** (1) Every export is renamed `terminal_*` → `ptec_terminal_*` (ARC-112); types and `TERM_*` constants keep their names. (2) `SharedCell` colors are display colors — live palette, OSC 10/11 defaults, bold brightening — and `attrs` gains `TERM_ATTR_DEFAULT_FG`, `TERM_ATTR_DEFAULT_BG`, `TERM_ATTR_HAS_COMBINING`; `SharedCell`'s layout is unchanged (ARC-101). (3) New `ptec_terminal_read_cell_grapheme` (ARC-101). (4) `TerminalObserverVtable` gains `on_event_v2` before `user_data` (48 → 56 bytes on LP64), with `TermEvent` and the `TERM_EVENT_*` kinds (ARC-114). (5) `ptec_terminal_scrollback_total_scrolled`, which first landed unreleased while the constant still read 3 and is part of v4. |
| v5 | 0.58.0 | Additive (ENH-038): scroll-aware damage — `TermScrollDelta` (16 bytes, `_Static_assert`ed), `ptec_terminal_scroll_delta_since`, `ptec_terminal_content_dirty_ranges_since`, and `TERM_SCROLL_FULL_REDRAW`, so a renderer blits on scroll and redraws only the rows whose content changed. Every v4 call behaves identically. |

The `ffi` feature gate (see [Building](#building)) changes how the surface is compiled, not the surface itself.

**Migrating from v3:** prefix every call with `ptec_`; zero-initialize `TerminalObserverVtable` (or set `on_event_v2`), because a v3-sized struct literal no longer fills the slot before `user_data`; mask `attrs` with the `TERM_CELL_*` bits if you compared it whole; and expect palette colors, not the fixed xterm table, in `SharedCell`.

Guard at startup:

```c
#include "terminal_core.h"
#include <stdio.h>
#include <stdlib.h>

Terminal *init_terminal_core(void) {
    if (ptec_terminal_abi_version() != TERM_CORE_ABI_VERSION) {
        fprintf(stderr,
                "terminal_core ABI mismatch: app %u, library %u\n",
                TERM_CORE_ABI_VERSION, ptec_terminal_abi_version());
        return NULL;
    }
    return ptec_terminal_create(80, 24, 10000);
}
```

The `_Static_assert`s in the header pin the struct layouts at compile time; the version check catches a library built against a different header at runtime.
